# Публикация RESPAWN на хостинге

Инструкция для демонстрационного магазина на SpaceWeb. Посетителю нужен только браузер. На хостинге должны быть PHP 8.5 с расширениями Laravel, MySQL 8 и HTTPS. Node.js, Composer и Docker на хостинге не нужны при установке готового пакета.

## 1. Получить пакет

Готовый пакет называется `respawn-hosting.zip`. В нём:

- `respawn/`: приложение, PHP-зависимости `vendor` и собранный интерфейс `public/build`;
- `respawn/.env.production.example`: шаблон серверных настроек без секретов;
- `respawn/database-install.sql`: схема новой базы, записи миграций, 4 категории и 24 демонстрационных товара;
- `respawn/REVISION.txt`: версия исходного кода;
- `START-HERE.md`: эта инструкция.

В пакете нет пользователей, заказов, отзывов, локального `.env`, логов, `.git`, Node.js-зависимостей и инструментов разработки. Реальная оплата и отправка писем отключены в приложении.

Чтобы получить новый пакет после изменения кода: откройте репозиторий в GitHub, затем **Actions → Hosting release → Run workflow**, выберите `main`. После успешного выполнения скачайте артефакт `respawn-hosting`. Внешний ZIP от GitHub содержит готовый `respawn-hosting.zip` и контрольную сумму. Этот процесс только собирает файлы, сам на хостинг их не отправляет.

## 2. Подготовить аккаунт и адрес

1. Зарегистрируйте виртуальный хостинг, например тариф «Старт». Покупка домена для первого запуска не обязательна.
2. В разделе «Сайты» найдите технический адрес вида `логин.temp.swtest.ru`.
3. Выберите PHP **8.5** для сайта.
4. Настройте HTTPS для адреса и проверьте, что браузер принимает сертификат без предупреждения. Возможность сертификата для технического адреса нужно проверить в панели конкретного аккаунта. Если она недоступна, для регистрации и входа потребуется собственный домен с HTTPS. Не отключайте защиту cookie ради запуска входа через HTTP.

У SpaceWeb на тестовом периоде нет SSH. Поэтому ниже описан запуск через файловый менеджер и phpMyAdmin. Тариф «Старт» акционный: по опубликованным условиям через год он автоматически меняется на «Взлёт». Перед оплатой проверьте текущую цену и срок в панели.

Источники: [условия «Старт»](https://help.sweb.ru/harakteristiki-tarifa-start_1601.html), [технический домен](https://help.sweb.ru/tehnicheskij-domen_65.html), [настройка сайта](https://help.sweb.ru/kak-sozdat6-sajt-v-paneli-upravleniya_980.html).

## 3. Загрузить файлы

1. Откройте файловый менеджер хостинга в панели.
2. Загрузите ZIP в домашний каталог аккаунта и распакуйте. Получится папка `respawn`.
3. Для сайта выберите публичную папку **`respawn/public`**. Папки `vendor`, `app`, файл `.env` и SQL должны находиться уровнем выше публичной папки.
4. Сохраните существующий `public/.htaccess`, он нужен для адресов `/catalog`, `/admin` и API. Включите показ скрытых файлов, если его не видно.
5. Если панель не позволяет поменять `public_html` на `respawn/public`, не выкладывайте туда весь проект. Сначала уточните настройку корня сайта в панели или у поддержки.

Права на каталоги обычно 755, на файлы 644. PHP должен иметь возможность записывать в `storage` и `bootstrap/cache`. На хостинге с PHP от имени владельца достаточно прав владельца, не ставьте 777 на весь проект.

## 4. Создать базу

1. В панели создайте **новую пустую базу MySQL 8** и пользователя с доступом к ней. Сохраните имя базы, имя пользователя, пароль и адрес сервера БД из панели.
2. Откройте phpMyAdmin именно для этой базы.
3. Выберите «Импорт» и загрузите `respawn/database-install.sql` из распакованного пакета.
4. После импорта появятся таблицы пользователей, каталога, заказов, отзывов, сессий, кэша и миграций. В `categories` должно быть 4 записи, в `products` 24, в `users` и `orders` 0.
5. Удалите `database-install.sql` с хостинга после успешной установки.

Этот SQL предназначен только для первой установки в пустую базу. Не импортируйте его повторно и не используйте для обновления уже работающего магазина. В нём намеренно нет `DROP TABLE` и `CREATE DATABASE`. Локальная база разработчика не переносится.

## 5. Заполнить серверные настройки

Скопируйте `respawn/.env.production.example` в `respawn/.env`. Заполните:

| Поле | Значение |
| --- | --- |
| `APP_URL` | Полный адрес магазина с `https://`, без завершающего слеша |
| `APP_KEY` | Новый ключ только для этой установки |
| `DB_HOST` | Адрес сервера MySQL из панели, часто `localhost` |
| `DB_DATABASE` | Имя созданной базы |
| `DB_USERNAME` | Пользователь этой базы |
| `DB_PASSWORD` | Пароль базы в двойных кавычках |

Остальные настройки уже подготовлены: production, отключённая отладка, защищённые cookie, сессии и кэш в БД, журнал с ограниченным сроком хранения. Специальные символы в пароле `.env` должны быть корректно экранированы; проще использовать сгенерированный длинный пароль из букв, цифр и символов `-_`.

Для нового `APP_KEY` выполните на своём Mac из папки проекта:

```bash
./vendor/bin/sail artisan key:generate --show
```

Команда только покажет новый случайный ключ и не изменит локальный `.env`. Если Sail не запущен, при установленном PHP можно использовать:

```bash
php -r 'echo "base64:" . base64_encode(random_bytes(32)) . PHP_EOL;'
```

Скопируйте целиком строку `base64:...` в `APP_KEY`. Не публикуйте ключ в GitHub и не меняйте его при обычном обновлении сайта. Если с локальным пакетом предоставлен отдельный приватный файл `APP_KEY.txt`, можно использовать его вместо генерации нового; этот файл не входит в публичный артефакт GitHub.

Файл `.env` находится вне `public`. Для него предпочтительны права 600, если PHP запускается от имени владельца. На сервер не копируется локальный `.env` из разработки.

## 6. Проверить сайт и создать администратора

1. Откройте главную страницу по HTTPS, каталог и товар.
2. Зарегистрируйтесь через обычную форму магазина с собственным паролем.
3. В phpMyAdmin откройте таблицу `users`, найдите **свой** аккаунт по адресу почты и измените только его `is_admin` с 0 на 1. Сохраните строку.
4. Перезайдите в магазин и откройте `/admin`. Пароль админки не выкладывается в README и не используется как публичный демо-пароль.
5. Для посетителей доступна обычная регистрация покупателей. Общего аккаунта с публичным паролем на сервере нет.

Если SSH уже доступен, вместо пунктов 2–3 можно использовать существующую команду:

```bash
php artisan shop:create-admin admin@example.com --name="Администратор"
```

Замените пример почты своим адресом. Команда запросит пароль скрыто. Убедитесь, что `php -v` в консоли показывает 8.5; версия командной строки может отличаться от выбранной для сайта.

## 7. Проверка после размещения

- Главная, `/catalog`, страница товара и обновление страницы по прямой ссылке открываются.
- Работают категории, поиск, сортировка и пагинация.
- Покупатель может войти, добавить товар в корзину и оформить демонстрационный заказ.
- Заказ появляется в кабинете и админке, остаток уменьшается; отмена возвращает остаток.
- Обычный покупатель не получает доступ к административному API.
- После статуса «Получен» можно оставить отзыв, администратор может его опубликовать.
- В консоли браузера нет ошибок, запросы выполняются к текущему HTTPS-адресу, а не к localhost.
- `/.env`, `/composer.json`, `/database-install.sql`, `/.git/config` не раскрывают содержимое файлов. Ответ SPA не является выдачей файла, но секретов в нём быть не должно.
- `/up` отвечает успешно. Эта проверка подтверждает загрузку приложения, отдельно проверьте каталог с запросом к БД.
- Нет запросов к локальному Vite на порту 5173. Файл `public/hot` не должен находиться на хостинге.

В демо не нужно вводить реальные адреса доставки и телефоны. Оплата имитируется, заказы не отправляются. Магазин демонстрирует интерфейс и серверные сценарии.

## 8. Обновления

Сначала сохраните резервную копию файлов и базы в панели. Новый ZIP распаковывайте в отдельную папку, не поверх работающего проекта: это исключает смешивание старых и новых PHP-зависимостей.

Перенесите в новый релиз серверный `.env` с прежним `APP_KEY` и сохраняемые файлы `storage/app`. Сессии и кэш в этой конфигурации находятся в БД. Скопируйте отсутствующие старые файлы из `public/build/assets` в новый релиз, чтобы уже открытые вкладки могли догрузить прежние JS-части; новый `manifest.json` оставьте из новой сборки.

Если меняется схема БД, нужны `php artisan migrate --force` с PHP 8.5 по SSH или запуск миграций администратором хостинга. Установочный SQL повторно не применяется. После успешной проверки переключите папку сайта на `public` нового релиза. Откат файлов после изменения схемы требует отдельной проверки совместимости.

Для первого запуска в тестовый период кэширование настроек командами не требуется. Когда появится SSH, можно выполнить `php artisan config:cache`, `php artisan route:cache`, `php artisan view:cache`. После изменения `.env` обновите кэш конфигурации. Очередь и планировщик для текущих функций магазина не требуются.

## 9. Проверка пакета перед первым размещением

31.10.2026 проверены 30 серверных тестов (197 проверок), 7 фронтенд-тестов, форматирование и production-сборка. Отдельно на временной MySQL 8.4 выполнены миграции, заполнение каталога, экспорт SQL и его импорт в другую пустую базу.

На готовом пакете без dev-зависимостей проверены главная страница, прямые ссылки каталога и товара, регистрация, сессии в БД, запрет административного API для покупателя, создание заказа, защита от повторной отправки и возврат остатка при отмене. Проверены наличие файлов из manifest и отсутствие ссылок на локальный Vite. Рабочая локальная база в этой проверке не использовалась.

Эта проверка не заменяет проверку HTTPS, прав файлов и настроек PHP на реальном хостинге после загрузки.
