# Публикация RESPAWN на хостинге

Рабочая демонстрация: **[bellium.alwaysdata.net](https://bellium.alwaysdata.net/)**. Для просмотра нужен только браузер. Магазин размещён на alwaysdata; Docker, Node.js и локальный компьютер разработчика для его работы не требуются.

Оплата демонстрационная, реальные деньги не списываются, товары и письма не отправляются. Пароль администратора не публикуется. Посетители могут зарегистрировать собственный аккаунт покупателя.

## 1. Подготовить пакет

В репозитории GitHub откройте **Actions → Hosting release → Run workflow**, выберите `main`. После успешного выполнения скачайте артефакт `respawn-hosting`. Внешний ZIP от GitHub содержит `respawn-hosting.zip` и его контрольную сумму.

Внутри пакета находятся:

- `respawn/`: приложение, production-зависимости `vendor` и собранный интерфейс `public/build`;
- `.env.production.example`: шаблон серверных настроек без секретов;
- `database-install.sql`: схема пустой установки с демонстрационным каталогом;
- `REVISION.txt`: версия исходного кода;
- `START-HERE.md`: инструкция размещения.

В пакет не попадают локальный `.env`, пользователи, заказы, отзывы, логи, `.git` и `node_modules`. Сборка GitHub только готовит файлы, автоматически на сервер их не отправляет.

## 2. Настроить alwaysdata

В панели [admin.alwaysdata.com](https://admin.alwaysdata.com/) используются следующие настройки:

| Раздел | Настройка |
| --- | --- |
| Environment | PHP 8.5 для командной строки и сайта |
| Web → Sites | Тип PHP, публичная папка `respawn/public` |
| Web → Sites | Адрес, выданный хостингом, и включённый Force HTTPS |
| Databases → MySQL | Отдельная база магазина |
| Databases → MySQL → Users | Отдельный пользователь только для базы магазина, SSL connection required |
| Remote access → SSH | Доступ для установки и обновления |

В рабочей установке проверены PHP 8.5.12 и MariaDB 11.8. Подключение к MariaDB использует драйвер `mysql`. Корень сайта: `/home/bellium/respawn/public`.

Загрузите ZIP по SFTP или SCP в домашний каталог аккаунта и распакуйте. Не размещайте весь проект в публичной папке: `.env`, `vendor`, `app` и SQL должны оставаться вне `public`. Сохраните `public/.htaccess`.

Временный ключ SSH можно добавить для размещения и удалить после проверки. Пароли панели и базы в Git не сохраняются. Файлы `storage` и `bootstrap/cache` должны быть доступны для записи PHP; права 777 для проекта не нужны.

## 3. Заполнить серверный .env

Скопируйте `.env.production.example` в `.env` на сервере и заполните:

| Поле | Значение |
| --- | --- |
| `APP_URL` | Полный HTTPS-адрес магазина |
| `APP_KEY` | Новый случайный ключ только для этой установки |
| `DB_CONNECTION` | `mysql` |
| `DB_HOST` | Адрес сервера из панели, для текущего аккаунта `mysql-bellium.alwaysdata.net` |
| `DB_DATABASE` | Имя новой базы магазина |
| `DB_USERNAME` | Отдельный пользователь базы |
| `DB_PASSWORD` | Его случайный пароль |
| `DB_COLLATION` | `utf8mb4_unicode_ci` |
| `MYSQL_ATTR_SSL_CA` | `/etc/ssl/certs/ca-certificates.crt` |

У `.env` установите права 600. Новый ключ можно получить через `php artisan key:generate --show`, затем сохранить в серверном `.env`. Не копируйте ключ из локальной разработки и не меняйте его при обычном обновлении сайта.

Шаблон уже включает production-режим, отключённую отладку, защищённые cookie, сессии и кэш в БД, синхронную очередь и запись писем в журнал. Соединение с БД на alwaysdata проверено с TLS и проверкой сертификата. Настройку CA нужно сохранить при последующих обновлениях.

## 4. Первая установка

Из папки приложения по SSH выполните:

```bash
php -v
composer check-platform-reqs --no-dev
php artisan migrate --force --no-interaction
php artisan db:seed --class=CatalogSeeder --force --no-interaction
php artisan config:cache --no-interaction
php artisan route:cache --no-interaction
php artisan view:cache --no-interaction
```

Composer здесь проверяет готовые зависимости, уже включённые в пакет. В новой базе создаются 4 категории и 24 товара: 23 опубликованы, один скрыт, один опубликованный товар отсутствует на складе. Пользователи и отзывы автоматически не создаются.

`database-install.sql` является альтернативой миграциям и сидеру только для новой пустой базы без SSH. Не импортируйте его после миграций или поверх существующих данных. При размещении на alwaysdata использованы миграции и сидер, установочный SQL не импортировался. Установочные ZIP и SQL после проверки удаляются с сервера.

## 5. Администратор

Для собственного закрытого администратора предусмотрена команда:

```bash
php artisan shop:create-admin admin@example.com --name="Администратор"
```

Замените пример почты своим адресом. Команда скрыто запросит пароль и не изменит существующих пользователей. Вход осуществляется через обычную форму магазина, административная страница находится по `/admin`.

Публичные пароли из раздела локальных демо-аккаунтов README на сервере не используются. `shop:demo-accounts` предназначена только для `local` и `testing`.

## 6. Проверка размещения

Проверьте главную, каталог, страницу товара, прямые ссылки после обновления страницы, фильтры, сортировку, корзину, регистрацию и вход. Демонстрационный заказ должен появиться в кабинете, уменьшить остаток и вернуть его при отмене. Покупатель не должен получать доступ к административному API. После получения заказа можно оставить отзыв для модерации.

Убедитесь, что HTTP перенаправляется на HTTPS, сертификат принимается браузером, а `/.env`, `/composer.json`, `/database-install.sql` и `/.git/config` не раскрывают файлы. В `public` не должно быть `hot` со ссылкой на локальный Vite. `/up` проверяет загрузку приложения, каталог дополнительно проверяет доступ к БД.

31.10.2026 на публичном HTTPS-адресе проверены регистрация, повторный вход, выход, каталог, фильтрация по наличию, скрытый товар, создание заказа, защита от повторной отправки, отмена с восстановлением остатка и история заказов. Административный API отвечает покупателю 403, история заказов гостю 401. В интерфейсе проверены фильтр категории, сортировка, товар и добавление в корзину. Проверены вход закрытого администратора и загрузка административного каталога. Временный покупатель и отменённый заказ удалены после проверки.

Перед размещением прошли 30 серверных тестов с 197 проверками, 7 фронтенд-тестов, форматирование и production-сборка. На отдельной MySQL 8.4 проверены миграции, сидер, экспорт и импорт установочного SQL. Локальная рабочая база при подготовке пакета не использовалась.

## 7. Последующие обновления

1. Сохраните резервную копию файлов и базы средствами хостинга.
2. Распакуйте новый пакет в отдельную папку релиза, не поверх работающего приложения.
3. Перенесите серверный `.env` с прежним `APP_KEY`, настройкой TLS базы и сохраняемые файлы `storage/app`.
4. Скопируйте отсутствующие старые файлы из `public/build/assets` в новый релиз для уже открытых вкладок. Новый `manifest.json` оставьте из новой сборки.
5. Выполните `composer check-platform-reqs --no-dev`, `php artisan migrate --force`, `config:cache`, `route:cache` и `view:cache` в новом релизе.
6. Переключите публичную папку сайта на `public` нового релиза и проверьте работу сайта.

Не выполняйте `migrate:fresh`, не импортируйте установочный SQL и не запускайте CatalogSeeder повторно поверх изменённого каталога: сидер обновляет цены и остатки. Откат файлов после изменения схемы требует отдельной проверки совместимости.

После изменения `.env` пересоздайте кэш командой `php artisan config:cache`. Постоянный процесс очереди и планировщик текущим функциям магазина не нужны. Коммит или push в GitHub сам по себе сайт не обновляет.
